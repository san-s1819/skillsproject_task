================================================================================
AUTOMOTIVE RECALL RAG AGENT - TECHNICAL ARCHITECTURE
================================================================================

SYSTEM OVERVIEW
---------------
A Retrieval-Augmented Generation (RAG) system for automotive recall queries
using lightweight TF-IDF embeddings and Google Gemini LLM.

================================================================================
CORE COMPONENTS
================================================================================

1. PROGRAMMING LANGUAGE
   - Python 3.13
   - Reason: Rich ML/AI ecosystem, easy prototyping

2. VECTOR DATABASE
   - ChromaDB 0.5.23 (Persistent Client)
   - Storage: Local filesystem (chroma_db/ directory)
   - Purpose: Store and retrieve document embeddings
   - Features: Automatic persistence, cosine similarity search

3. EMBEDDING MODEL
   - Model: Sentence-Transformers (all-MiniLM-L6-v2)
   - Type: Neural semantic embeddings
   - Implementation: sentence-transformers 5.2.2
   - Backend: PyTorch 2.10.0 (CPU-optimized)
   - Embedding Dimension: 384
   - Speed: ~14,000 sentences/sec on CPU
   - Quality: Excellent semantic understanding
   - Benefits: Handles synonyms, paraphrasing, and semantic similarity

4. LANGUAGE MODEL (LLM)
   - Model: Google Gemini 2.0 Flash Exp
   - API: Google GenAI SDK (official Python library)
   - SDK Version: google-genai 1.61.0
   - Authentication: API key via environment variable
   - Purpose: Natural language understanding and response generation
   - Benefits: Cleaner code, automatic retries, better error handling

5. DOCUMENT STORE
   - Format: Plain text files (.txt)
   - Location: data/recalls/
   - Count: 15 recall documents
   - Metadata: Extracted from filename (manufacturer_model_year_component.txt)

================================================================================
ARCHITECTURE FLOW
================================================================================

USER QUERY
    ↓
[1] QUERY EXPANSION (vector_store.py)
    - Expand abbreviations (RAV4 → RAV4 RAV-4)
    - Add synonyms (brake → brake braking)
    ↓
[2] TF-IDF VECTORIZATION (scikit-learn)
    - Transform query to 1000-dimensional sparse vector
    ↓
[3] VECTOR SEARCH (ChromaDB)
    - Cosine similarity search
    - Retrieve top-k documents (default k=3)
    ↓
[4] CONFIDENCE SCORING (vector_store.py)
    - Analyze similarity score distribution
    - Calculate confidence: HIGH/MEDIUM/LOW
    ↓
[5] PROMPT CONSTRUCTION (llm_client.py)
    - Format retrieved documents with [1], [2], [3] citations
    - Add instructions for source attribution
    ↓
[6] LLM GENERATION (Gemini API)
    - Generate response with inline citations
    - Include "Sources:" section
    ↓
[7] RESPONSE DELIVERY
    - Display confidence score
    - Show cited sources
    - Return formatted response

DATA STRUCTURES

DOCUMENT OBJECT:
{
    'content': str,              # Full document text
    'filename': str,             # Source filename
    'filepath': str,             # Absolute path
    'metadata': {
        'manufacturer': str,     # e.g., 'honda'
        'model': str,            # e.g., 'civic'

}

RETRIEVAL RESULT:
{
    'documents': [               # List of retrieved documents
        {
            'rank': int,         # 1, 2, 3, ...
            'document': {...},   # Document object
            'similarity_score': float,  # 0.0 to 1.0
            'distance': float    # ChromaDB distance metric
        }
    ],
    'confidence': {
        'level': str,            # 'HIGH', 'MEDIUM', 'LOW'
        'score': float,          # Top similarity score
        'gap': float,            # Score difference (top - second)
        'reason': str            # Human-readable explanation
    },
    'query_expanded': bool,      # Whether query was expanded
    'original_query': str,       # User's original query
    'expanded_query': str        # Expanded version (if applicable)
}

STORAGE:
- TF-IDF index: ~100KB

================================================================================
RETRIEVAL ALGORITHM
================================================================================

SIMILARITY METRIC: Cosine Similarity
- Formula: cos(θ) = (A · B) / (||A|| × ||B||)
- Range: 0 to 1 (1 = identical, 0 = orthogonal)
- ChromaDB uses cosine distance: distance = 1 - similarity

CONFIDENCE SCORING (Semantic Embeddings):
- HIGH:   top_score > 0.7 AND score_gap > 0.1
- MEDIUM: top_score > 0.5
- LOW:    top_score ≤ 0.5

QUERY PROCESSING:
- No query expansion needed (semantic model handles variations)
- Direct encoding: query → 384-dimensional embedding
- Cosine similarity search in embedding space

API INTEGRATION

GEMINI API (via SDK):

- Error Handling: Automatic retries built into SDK
- Timeout: Configurable (default: 30 seconds)

================================================================================
ERROR HANDLING
================================================================================

LOGGING FORMAT: [ClassName.method_name] Error: {ErrorType}: {message}

KEY ERROR POINTS:
1. Vector Store Initialization
   - Missing data directory → FileNotFoundError
   - Document loading failures → UnicodeDecodeError
   - ChromaDB corruption → KeyError

2. LLM Client
   - Missing API key → ValueError
   - Rate limiting → 429 error with backoff
   - Network issues → ConnectionError

3. Query Processing
   - Empty results → Return "no relevant information" message
   - API failures → Retry with exponential backoff

================================================================================
DESIGN TRADE-OFFS
================================================================================

Sentence-Transformers vs TF-IDF:
✓ Pros: Semantic understanding, handles synonyms, better accuracy
✗ Cons: Larger install size (~1GB vs ~100MB), slightly slower
Decision: Using semantic embeddings for superior search quality

ChromaDB vs FAISS:
✓ Pros: Automatic persistence, cleaner API, easier setup
✗ Cons: Slightly slower for very large datasets

Google GenAI SDK vs Direct REST API:
✓ Pros: Cleaner code, automatic retries, better error handling, official support
✗ Cons: Slightly larger install size (~50MB more)
Decision: Using SDK for better maintainability and developer experience
